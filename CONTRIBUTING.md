# Contributing

Help users find relevant sources, understand implementation outcomes and inspect exceptions.

## Choose one record

| Contribution | Template | Destination |
|---|---|---|
| Standard, model or vendor capability | [Catalogue record](templates/catalogue-record.md) | catalogue/records/ and catalogue/index.yaml |
| Business question and selection guide | [Use case](templates/use-case.md) | use-cases/ |
| Sourced implementation outcome | [Implementation](templates/implementation.md) | evidence/implementations/ |
| Limitation, tradeoff or boundary | [Exception](templates/exception.md) | evidence/exceptions/ |

Search existing IDs and the [discovery backlog](catalogue/discovery-backlog.md) first. Extend an existing record rather than create another copy for a vendor or category view.

## Submit

1. State the user question and bounded scope.
2. Add official references and distinguish reported claims from your assessment.
3. Record missing versions, costs and outcomes as unknown; do not estimate them.
4. Link related catalogue IDs, cases and exceptions. Update industry membership where applicable.
5. Submit a pull request with sources checked, changes, conflicts of interest and open questions.

Follow the [evidence policy](guides/evidence-policy.md), [classification](guides/classification.md) and [governance](GOVERNANCE.md). Records remain draft until a reviewer other than the author approves them. Maintainers can run [content checks](guides/repository-structure.md); no implementation or benchmark is required to contribute a sourced record.

Do not submit personal data, confidential schemas, restricted standards or client material without publication authority. AI-assisted summaries require source checking and human review. Contributions are accepted only under the [licensing policy](LICENSES/README.md) for material the contributor is authorised to license.
